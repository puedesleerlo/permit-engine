How it decides

Twelve stages, and each has one owner. The models read and answer, code checks and counts, Rego decides, and an officer handles what is sent to one.

See it first

One application followed through its hazards, the trees and the equations to the final result, then the three experiments.

One case, stage by stage

Stages 1 to 8 run once per case, ahead of time, and their answers are stored. Stages 9 and 10 use the weights of the moment, and need no model call.

  1. 1

    Basic checks

    Rego

    Is the fee paid, is the form complete, is the date in the permitted window? If not, the case stops here and no model is called.

  2. 2

    Link and extract

    Agentic LLM

    First pass. For each kind of proof a race can need, it says found or absent, gives fields with quotes, and lists documents that fit no kind. It also reads expected spectators from the description.

  3. 3

    Quote check

    Code

    Each quote must appear in the named attachment, and each value inside its quote, or that field counts as absent. The form and the cover letter are never allowed sources.

  4. 4

    Judge

    Agentic LLM

    Second pass, in a fresh context. It reads the attachments behind verified fields and the case’s typed values, never the cover letter, and gives one verdict per kind of proof.

  5. 5

    Requirement check

    Rego

    Code compares fields with the form first. A mismatch makes the record contradicted, whatever the verdict said. Rego then gives each requirement a status, citing a clause.

  6. 6

    Rule answers

    Rego

    Answers every question that needs only the form and extracted fields, such as “is the crowd over 800?”.

  7. 7

    Hazard screen

    Rego

    Decides which hazards apply, by rules only: traffic if a road closes, crowd pressure if the crowd is 300 or more, medical always.

  8. 8

    Tree questions

    Jev

    One request per case, with typed values, evidence records and whole plan documents. Jev returns a probability for each of its questions on the hazards that apply. It never reads the cover letter.

  9. 9

    Tree arithmetic

    Code

    Gives likelihood and severity per hazard, how unsure each leaf is, how much each leaf contributed, the risk sum and the highest severity.

  10. 10

    Decision

    Rego

    The decision table, first match wins. It gives a row, a route, a reason and the clauses behind it.

  11. 11

    Officer ruling

    Officer

    For a case sent to an officer: a ruling and a one-line reason. In this demo an LLM following the expert rubric does this, labelled as simulated. In a real deployment, a person would.

  12. 12

    Log

    Code

    Each stage is written as an event, with the hashes of everything the decision used. If the write fails, the decision does not take effect.

A worked example

Illustrative. All numbers are made up to show the working, and none is a result. A running charity applies for a 5K: 400 runners, no spectators mentioned, one road closed, no arterial road, a June date, an ambulance on site, a nearby hospital and a valid insurance certificate. No police escort letter is attached.

1. Basic checks
The fee is paid, the form is complete and the date is allowed. Pass.
2. Link and extract
The certificate of insurance is found, with its fields. The police escort letter and email are absent. No documents are left over.
3. Quote check
The insurance quotes appear word for word in the certificate, and each value is inside its quote.
4. Judge
Insurance is supported. The escort has no document, so its verdict is unsupported, with the reason “no evidence”.
5. Requirement check
The certificate’s venue and dates match the form, so insurance is met. A police escort is not checked as a requirement, so it does not stop the case.
6. Rule answers
Arterial road no, crowd over 800 no, hot date yes, far hospital no.
7. Hazard screen
Traffic applies because a road closes, crowd pressure because 400 is 300 or more, and medical always.
8. Tree questions
Jev gives a probability for each of its questions, such as 0.8 that the traffic plan is adequate.
9. Tree arithmetic
Traffic: 0.217 × 0.28 = 0.061. Crowd: 0.072 × 0.22 = 0.016. Medical: 0.080 × 0.31 = 0.025. Risk: 0.102.
10. Decision
With a lower threshold of 0.08 and an upper threshold of 0.25, nothing earlier fires. The risk is inside the review band, so row 6 sends the case to an officer. With a supported escort letter, the same application would sum to about 0.06 and be approved at row 4.
11. Officer ruling
The simulated officer reads the documents and the rubric, and rules with a one-line reason. If it approves, the permit is issued, with the ruling as its parent event.
12. Log
Every stage above is written as events, with the hashes of what was used.

Who does what

In the design, no model decides. The one exception is in this demo: an LLM plays the officer and does decide the cases sent to an officer, always labelled as simulated.

Project ownerThe author, a person. Runs the commands, and plays the policy owner and the steward. The policy owner owns the trees and settings and releases changes. The steward owns the evidence map.Acts without a role: each action is logged with one. The split between the two roles is a process rule, because one person plays both and nothing enforces it.

Why one pass reads the cover letter

If the LLM never saw it, a test of tone would pass by construction and prove nothing. So the first pass reads it, and code stops it from being evidence. The second pass and Jev never see it, and tests check that. The simulated officer does read it, and its rubric tells it to ignore tone.
