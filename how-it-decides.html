How it decides

Permit Engine turns a street-race permit application into a decision in twelve stages. Models read and answer, code checks and counts, written rules in the policy language Rego decide, and an officer handles what is sent to one.

The twelve stages, and who owns each

Stages 1 to 8 run once per case, ahead of time, and their answers are stored. Stages 9 and 10 use the current weights and need no model call.

  1. 1

    Basic checks

    Rego

    Is the fee paid, is the form complete, is the date in the permitted window? If not, the case stops here and no model is called.

  2. 2

    Link and extract

    Agentic LLM

    First pass. For each kind of proof a race can need, it says found or absent, gives fields with quotes, and lists documents that fit no kind. It also reads expected spectators from the description.

  3. 3

    Quote check

    Code

    Each quote must appear in the named attachment, and each value inside its quote, or that field counts as absent. The form and the cover letter are never allowed sources.

  4. 4

    Judge

    Agentic LLM

    Second pass, in a new session with no memory of the first. It reads the attachments behind verified fields and the case’s typed values, never the cover letter, and gives one verdict per kind of proof.

  5. 5

    Requirement check

    Rego

    Code compares fields with the form first. A mismatch makes the record contradicted, whatever the verdict said. Rego then gives each requirement a status, citing a clause.

  6. 6

    Rule answers

    Rego

    Answers every question that needs only the form and extracted fields, such as “is the crowd over 800?”.

  7. 7

    Hazard screen

    Rego

    Decides which hazards apply, by rules only: traffic if a road closes, crowd pressure if the crowd is 300 or more, medical always.

  8. 8

    Tree questions

    Jev

    One request per case, with typed values, evidence records and whole plan documents. Jev returns a probability for each of its questions on the hazards that apply. It never reads the cover letter.

  9. 9

    Tree arithmetic

    Code

    Gives likelihood and severity per hazard, how unsure each leaf is, how much each leaf contributed, the risk sum and the highest severity.

  10. 10

    Decision

    Rego

    The decision table, first match wins. It gives a row, a route, a reason and the clauses behind it.

  11. 11

    Officer ruling

    Officer

    For a case sent to an officer: a ruling and a one-line reason. In this demo an LLM following the expert rubric does this, labelled as simulated. In a real deployment, a person would.

  12. 12

    Log

    Code

    Each stage is written as an event, with the hashes of everything the decision used. If the write fails, the decision does not take effect.

Who does what

In a real deployment, no model decides. In this demo, an LLM plays the officer and decides the cases sent to an officer, always labelled as simulated.

Each part of the system, its job, and what it never does
Part, and its jobNever
Agentic LLMFinds evidence for each kind of proof the case needs, extracts fields with quotes, judges each record, and lists documents that fit no kind. Two fixed passes with no tools.Decides, issues a permit, or changes a setting.
JevA second model with fixed weights. Answers four narrow questions as probabilities: whether each of the three plans is adequate, and whether the venue is too confined.Reads the cover letter, or judges evidence.
CodeGenerates data, checks quotes, compares fields, does the arithmetic and trains.Holds policy values. Those are in settings files.
Rego, through OPABasic checks, requirement status, rule questions, the hazard screen and the decision table.Calls a model, the network, the clock or a random number.
Simulated officerAn LLM standing in for a person. It follows the expert rubric, rules with a one-line reason, and gives a level for each tree. Always labelled as simulated.Reads labels or hidden case facts, uses tools, or changes a setting.
Project ownerThe author. Owns the trees, the settings and the evidence map, and releases changes.Acts without a role: each action is logged with one.
