Permit Engine

Decisions split into parts you can check and correct. An agentic LLM reads the evidence, Jev answers narrow questions, written rules decide, and an officer handles anything uncertain. In this demo, every application is synthetic and an LLM stands in for the officer.

What is real and what is simulated

Some readers will test these claims, so here they are first.

Simulated, or written by the author

  • All applications are synthetic. A script writes them from one seed, for a fictional city with an invented ordinance. No real applicant or event is involved.
  • The labels were written by the author. A hidden truth table sets each case’s risk levels. Results show how well the trees learn that table, not how real events behave.
  • An LLM stands in for the officer in this demo. It follows an expert rubric, which is that truth table in plain words. A real deployment would use a person.
  • The replay is not live. You watch a finished run, stored as files.

Real, and running

  • The code exists: the generator, rule files, reader, code checks, trees, training, event log, export and replay.
  • Written rules decide. Rego runs through Open Policy Agent (OPA), and code does the arithmetic. Any logged decision can be reproduced with no model calls.
  • The agent is two fixed passes with no tools. One links documents and quotes fields, and one judges them. There is no loop. “Agentic LLM” is the name used on this site, and this is all it means here.
  • Every officer review teaches the trees, not only the reviews that disagree with the system.
  • The run behind the link. When this page was built, the exported run held real answers: the agentic LLM and Jev read these synthetic documents ahead of time, and their answers are stored and replayed.

Not everything once described is built. See what is not built, and what has changed since the printed poster.

Four parts, each with one job

The models read and answer. Code checks and counts. Written rules decide.

  1. Check the evidence

    An agentic LLM links each document to the kind of proof it is, quotes what it found, and gives a verdict. Code then checks every quote against the document and every field against the form.

  2. Assess the risk

    Each hazard has a likelihood tree and a severity tree. Rules, evidence verdicts and Jev answer their questions, and code does the arithmetic. Risk is likelihood times severity, summed over the hazards that apply.

  3. Apply the rules

    A decision table written in Rego goes from top to bottom. The first match returns the form, proposes a denial, sends the case to an officer, or approves.

  4. An officer settles the rest

    In a real deployment that is a person. In this demo an LLM following a written rubric stands in, and every one of its rulings is labelled as simulated.

Why split the decision

This design assumes that offices and regulated firms want AI help with decisions they must be able to explain. A baseline in the experiment tests that view: one LLM that reads the application and answers approve or deny.

  • It does not show its working

    A model asked to approve or deny gives an answer, not the facts and rules behind it.

    Here, each case logs its evidence, tree values and the rule that fired.

  • Tone may sway it

    A pushy letter may win a yes that a plain one would not.

    Here, code stops a cover letter from being evidence, and the second pass and Jev never read it. The Testing page gives the measured flip rates.

  • Its mistakes have no address

    When it is wrong, there is no clear part to correct.

    Here, a review moves named leaf weights, with old and new values on screen. A bad one is removed by building a new run.

The experiment

If the models that read the evidence stay frozen, can the weights of a decision tree learn from labelled applications and improve decisions on cases they never saw?

What this can show. Whether the mechanism works: leaf weights can learn from labels, recover a planted pattern, and take in an officer’s reviews, while written rules keep the final say.

What this cannot show. That the risk levels describe real events. The trees ask about the same factors the truth table uses, so training is close to guaranteed to learn it. The strongest objection is that the demo only proves its own machinery runs, and that objection stands until labels the author did not write exist.
