Learning

The reading models stay frozen. What learns is a small table of weights on the leaves of the trees, and two thresholds. A person can read all of it.

See the results

Two sets of weights, kept apart

Each one answers a different question. Mixing them up would make the results mean less, so the site labels which is which.

Trained on labelled cases

Fitted on the training split, then released under a version. These are what the sealed test measures.

Each tree starts from its first guess, counted as 2 cases per leaf. Then, 6 times over, each labelled case is split across the leaves in proportion to how much of it reached each leaf and how well that leaf explains the label, and those shares are added to the leaf’s counts. This reads stored answers and calls no model.

The first guess, corrected by reviews

What the replay shows. It starts from the first guess, because trees that are already trained give a flat line. These weights have no test result, and a new run discards them.

The test cases never appear in the replay, so they cannot be corrected.

What one officer review does

Every officer review teaches the trees, not only the reviews that disagree with the system. Teaching only from disagreements made the blind first guess slightly worse in simulation, because it taught only from cases that guess got wrong.

  1. 01The officer reviewsIt reads the documents, the decision and the rubric, and gives a ruling, risky or not, a one-line reason and a level for each tree.
  2. 02A network works backOne Bayesian network: tree levels lead to risk, and risk leads to the outcome. Named levels are fixed as evidence.
  3. 03Leaf counts moveShares are added to the leaves this case reached, after old counts there are multiplied by 0.93.
  4. 04Thresholds are re-chosenEvery 10 reviews, because thresholds fitted to one set of weights do not fit the next.

A review that disagrees is still shown as a correction, with its old and new weights and the counts behind them. One review moves a leaf that has seen many cases only a little, on purpose.

Later cases use the new weights and record the version they used. Curve points are read on cases the officer never reviewed, so a reviewed case does not score its own lesson.

Thresholds are chosen on a separate set of labelled cases from the ones the curve is read on.

Who the officer is

Simulated officer: an LLM following the expert rubric. That label appears wherever a ruling does.

An LLM stands in for a person, because no person can rule on every case while visitors watch. The rubric is the truth table in plain words, so its measured accuracy mostly shows that it followed the rubric. It has no tools, and it reads no labels or hidden case facts. A real deployment would use a person.

What the replay’s plots should show

This is what the design expects, and why. The numbers for the finished run are in the results section, whichever way they fell.

Right risk level: rises

How often a tree’s most likely level is the expert’s level. Reviews carry the expert’s rule into the weights, so this is the number that should rise.

Decided without an officer: near flat

Many cases can never be decided automatically, whatever the weights say: a missing or failed requirement, a contradiction, or a document that fits no kind. Better weights cannot move those.

Precision: near its target

The share of automatic approvals not labelled risky. Thresholds are re-chosen to aim at the same 5% limit on risky approvals each time, so a flat line shows that safety did not drop. It does not show that safety improved.

What this plot does not prove

The officer follows a rubric written from the same truth table as the labels. So the plot shows corrections carrying a stated rule into the weights, and it finds nothing new. It shows the mechanism, not how a person would behave, and not how real events go.

The planted gap

Can the system point at a question it is missing? The truth table raises traffic likelihood on routes with 3 or more major crossings, and the first traffic tree does not ask about crossings. This is planted on purpose.

The signal. A tree is flagged when its mean leaf entropy is the highest of all trees and above 0.6, counting leaves with enough cases. High entropy means the cases reaching a leaf have mixed outcomes, which is a reason to look, not proof.

The change. The new question was written in advance and is labelled so. No model drafted it. It is a rule question from the form, so it needs no model call and no re-read.

The release. Candidates are trained with and without it, and the report gives validation loss for both. Only the policy owner’s release command makes it official. Step through this on the architecture page.

Entropy and loss are different signals

Loss on a case says how wrong that prediction was, and it drives training. A trained leaf’s entropy says the cases reaching that branch have mixed outcomes, which points to a missing question. A single confident mistake has low entropy and high loss.

Who can change what

Weights are data, and they can only change through these steps. One person plays the policy owner and the steward here, so the split between them is a process rule that nothing enforces. Each action is logged with its role.

A SQLite file whose triggers reject updates and deletes. It guards against mistakes, not against someone with access to the file.
Reproducing a decision
A command re-runs a logged decision from stored inputs with no model calls, and checks that the result is identical. It refuses if the rules, settings, application or arithmetic have changed.
Undoing
Released weights never change in place, and a new version sits beside the old one. A bad correction is removed by building a new run.
