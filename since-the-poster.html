What has changed since the poster

The poster is printed and cannot change, so this page stays here for good. It sets out what the poster claimed, what is true now, and what is not built.

When the poster was printed, it described a design as if it were finished. Parts of that design also did not hold up in review, so they were replaced. The earlier version of this site described a different decision rule and has been rewritten to match what runs.

The poster, line by line

Words in quotation marks are the poster’s, shortened in places.

  • The poster says

    “What I built: a working prototype that keeps fact-checking, risk and rules separate.”

    What is true now Corrected

    When the poster was printed, no engine existed, only a design. The parts have been built since, for one demo: a generator, rules, a reader, trees, training, a log and a replay. It runs on synthetic data, on one Mac. It is an experiment, not a working permit system.

  • The poster says

    “A city office deciding permits for public events in parks: concerts, races, festivals.”

    What is true now Changed

    One event type, a street race, for a fictional city with an invented ordinance. Every application is synthetic.

  • The poster says

    “Pins down what each claim means (‘Lincoln Park’: which one?) and checks it against documents and city records.”

    What is true now Changed

    There are no city records. An agentic LLM links documents to a small evidence map, in two fixed passes with no tools, and quotes what it found. Code checks each quote and compares fields with the form.

  • The poster says

    “TypeSafe Jev supplies the likelihood and harm scores.”

    What is true now Changed

    Jev answers four narrow questions as probabilities. Trees combine those with rule answers and evidence verdicts, and code works out likelihood and severity.

  • The poster says

    “Statistics: checks that ‘90% sure’ is right 9 times in 10, using officers’ rulings.” The poster’s references point to this method.

    What is true now Changed

    That fit is not used anywhere. The report gives Jev’s calibration error against the hidden facts, with no fit applied.

  • The poster says

    “Fee paid. Park free. Under 500.”

    What is true now Changed

    The basic checks are the fee, a complete form and a date in the permitted window. There is no crowd limit. Crowd size feeds the hazard screen and the trees instead.

  • The poster says

    “On hold: the city asks the organizer for the police escort letter. If it never arrives, an officer decides.” And: “Proof is missing: applicant asked to send it.”

    What is true now Not built

    Cut. Nothing writes to an applicant. A missing requirement goes straight to an officer, and an absent escort letter only moves the risk. In the worked example, that 5K now reaches an officer through the review band.

  • The poster says

    “Five possible results, checked in this order.”

    What is true now Changed

    A decision table of seven rows, first match wins, in Rego. Its routes are returned, proposed denial, officer and approved.

  • The poster says

    “Approved, a person checks 1 in 10.”

    What is true now Not built

    There are no random spot checks. In this demo a simulated officer reviews every decided case except a returned form, and every review teaches the trees. Spot checks wait for real traffic.

  • The poster says

    “Uncertain cases and every denial go to an officer. Their rulings tune how cautious it is.”

    What is true now Changed

    Those cases do go to an officer, but in this demo the officer is an LLM following a written rubric, always labelled as simulated. Its reviews move leaf weights, and thresholds are re-chosen. A real deployment would use a person.

  • The poster says

    “After each case: when an officer overturns a decision, the ‘strong enough’ bar moves up or down.”

    What is true now Changed

    Replaced. A risk sum is compared with two thresholds, and a review moves the weights on the leaves that case reached.

  • The poster says

    “Every week: repeated mistakes become new cautious checks. Only the policy owner can change the rules.”

    What is true now Not built

    Nothing turns repeated mistakes into checks. One tree change exists, a question planted and written in advance, and only the policy owner’s release command makes it official.

  • The poster says

    “Before any change: it is tested on past cases first and can be undone.”

    What is true now Changed

    A tree change is read on validation cases before release, and released versions never change in place. Nothing forces that reading step, and it is the policy owner’s job. Corrections are undone by building a new run.

  • The poster says

    “Every decision records its facts and the exact rules in force, so an auditor can retrace it.”

    What is true now Holds

    This holds, for a run. Each decision logs the hashes of what it used, and a command reproduces it with no model calls, or refuses and says why.

  • The poster says

    “A yes/no risk flowchart… Medium risk… the end point sets how strong the evidence must be.”

    What is true now Changed

    Replaced by two small trees per hazard, for three hazards. A leaf holds weights over three levels, and risk is likelihood times severity, summed.

  • The poster says

    “240 test cases: 60 applications × 4 tones.”

    What is true now Changed

    The design has 160: 100 sealed test requests, plus 60 tone cases made from 20 of them. The final report scores the 100, and the tone cases count only for flips.

  • The poster says

    “Pressure can’t buy a permit: pushy wording is ignored.”

    What is true now Corrected

    Too strong. Code stops a cover letter from being evidence, and the second pass and Jev are never sent it. But the first pass reads it, so tone could still change what it links or quotes. The Testing page gives the measured flip rates.

  • The poster says

    “Permit Engine vs. one AI asked ‘approve or deny?’. Results pending.”

    What is true now Changed

    The comparison is written as code and reported beside the pass rule, along with Jev asked directly. See the results for what was run.

  • The poster says

    “Can be stopped and undone: one switch sends all cases to people.”

    What is true now Changed

    The switch exists and a test covers it. Undoing an issued permit is not built.

  • The poster says

    “Same pattern, any high-stakes queue.”

    What is true now Corrected

    An idea, not a result. Nothing has been built or tested outside one synthetic event type.

Not built

Described on the poster, on an earlier version of this site, or in the design, and not in the system today. Nothing in this section runs.

  • Not built

    Asking an applicant once for missing proof

    The letter path, the waiting state and the second read are cut. A missing requirement goes to an officer.

  • Not built

    1-in-10 spot checks and blind rulings

    These wait for real traffic. Here, labels do that job.

  • Not built

    A person as the officer

    There is no officer screen. An LLM stands in, and the project owner’s real corrections come from a local file.

  • Not built

    Sorting a mistake by whose it was

    The design names four kinds: the AI, a person, a changed context, or an exception. In this build, a review either confirms the system or corrects it.

  • Not built

    Appeals and event outcomes

    No appeals, no recording of what happened at an event, and so no labels from real outcomes.

  • Not built

    Revoking a permit, and withdrawn applications

    A case ends at approved, returned or denied.

  • Not built

    Learning how to learn

    Tuning how fast the system learns and how much officers check. It stays an idea.

  • Not built

    Repeated mistakes turned into cautious checks

    The weekly loop on the poster. The one tree change here was written in advance. No model drafts a question.

  • Not built

    A proposals screen and What if reports

    A release command makes weights official, and no screen is public.

  • Not built

    More event types

    One event type, a street race. No other has been tried.

  • Not built

    Backups, and a cost count before a re-read

    Both are in the design. Neither command exists yet.
