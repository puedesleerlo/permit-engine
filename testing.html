Testing and results

Permit Engine was trained on 180 synthetic permit requests and tested once on 100 it had never seen. It passed the rule set in advance: lower loss, more approvals and no clear safety failure. Its trees picked the answer-key level 89.4% of the time, against 68.2% for the untrained first guess. The author wrote the answer key, so these scores show the method can learn it, not that it predicts real risk.

What we tried

Each experiment and its result. Real models means the real LLM and Jev read synthetic cases. Simulation means noisy stand-ins took their place.

Three design choices the tests changed

  • How a review moves the weights. Backprop led at first, only because its step size was tuned on data from after a simulated change. With settings fixed in advance, a Bayesian network did better.
  • Which reviews teach. Learning only from disagreements made loss worse, from 0.748 to 0.798, so every review now teaches.
  • What counts as passing. The pass rule was tested before use. In simulation, the first rule passed a working system only 58% of the time, so it was replaced before the test opened.

What happens when something goes wrong

These nine, from the 33 failure paths mapped out for this system, show how each part responds. 26 of the 33 have a test so far, 17 of them complete.

  • The LLM invents or alters a quote

    Code checks every quote against the named document. A quote that does not match counts as no evidence.

    Tested

  • A cover letter is used as proof

    Code refuses it as a source, and the second pass and Jev never see it.

    Tested

  • A letter disagrees with the form

    Code compares every field with the form, and row 1 sends the case to an officer. This is the Riverside case on the Overview.

    Tested

  • Instructions are hidden in an attachment

    The LLM has no tools to act on them, and code still compares the fields.

    Next: score whether these instructions changed any verdict.

    Partly tested

  • A model is down or slow

    After retries the case goes to an officer, and nothing is approved.

    Next: test a real outage, not only its effect on a case.

    Partly tested

  • The rules engine fails

    The system fails closed, and an officer reviews the case.

    Tested

  • Answer-key labels reach a part that must not see them

    Tests check which files may open the labels, and a failing test stops the run.

    Tested

  • Someone reopens the sealed test

    A ledger allows one look per dataset, and refuses a second run.

    Tested

  • A decision no longer matches its versions

    Each decision records the hashes of what it used, and reproducing it is refused if they differ.

    Tested
